# Audit Tsuzuku — 8 octobre 2026

## Méthode et périmètre

- **Statique** : `typecheck` (0 erreur), `lint` (0 erreur, 2 warnings préexistants),
  suite `src/` (189/189 verts), recherche de motifs (`TODO`, `console.log`,
  couleurs codées en dur, `window.confirm`, `<img>` sans repli, `document.title`).
- **Dynamique** : Playwright (Edge) sur le serveur dev `127.0.0.1:8080` —
  13 vues en 1440 px + dashboard / liste / watch en 390 px + fiche titre :
  erreurs console, `pageerror`, requêtes ≥ 400, débordement horizontal,
  `h1`, images cassées, boutons sans nom accessible. Captures dans `screenshots/audit-*`.
- **Limites** : serveur dev avec auth désactivée (`VITE_AUTH_ENABLED=false`) —
  les appels `/api/*` sous auth renvoient `503 {"error":"Auth disabled"}`.
  Les parcours sociaux nécessitant un backend réel n'ont pas pu être testés
  de bout en bout. La preview du build de production reste bloquée par
  l'absence de `pglite.data` dans la fonction Vercel (problème connu, inchangé).

## Verdict

Aucun bug bloquant. Socle sain : zéro erreur console, zéro débordement,
zéro bouton sans nom, 12 vues sur 13 avec un `h1` unique. Les 8 constats
ci-dessous sont des bugs réels mais de sévérité moyenne à faible, classés par
priorité de correction.

## Constats

### 1. Erreur API affichée brute sur les listes partagées — Moyen (UX)

- **Fichiers** : `src/components/tsuzuku/use-shared-lists.ts:31,61,94,128`
  → `src/components/tsuzuku/lists-view.tsx:190`
- **Repro** : ouvrir `/lists` quand l'API échoue (constaté en dev : `503`).
  La page affiche littéralement « Erreur 503 », sans explication ni action.
- **Cause** : `err.message` est injecté tel quel dans l'UI.
- **Piste** : message convivial (« Impossible de charger tes listes ») +
  bouton « Réessayer » qui relance le chargement. Même traitement pour
  `use-shared-lists.ts:94,128` (détail d'une liste).

### 2. Images CDN mortes sans image de repli — Moyen (visuel)

- **Fichiers** : `src/components/tsuzuku/dashboard.tsx:474,556`
  (hero « Continuer » + chips), `src/components/tsuzuku/profile-avatar.tsx:28`,
  plus 12 autres `<img>` bruts (`weekly-digest.tsx:91`,
  `calendar-view.tsx:298`, `friends-view.tsx:380`, `lists-view.tsx:476,749,830,872`,
  `activity-feed.tsx:174`, `notifications-center.tsx:294`,
  `friend-compare.tsx:15`, `profile-view.tsx:325,606`, `watch-page.tsx:340`,
  `entry-modal.tsx:210`).
- **Repro** : constaté en QA — le cover Jujutsu Kaisen
  (`bx40028-BvyE5qHCEzcs.png`) renvoie 404, AniList ayant fait tourner ses
  hash. Seuls `Cover` et les cartes de la liste dégradent proprement
  (initiales) ; partout ailleurs apparaît l'icône d'image cassée.
- **Piste** : faire passer les vignettes par `Cover`, et ajouter un `onError`
  à `ProfileAvatar` (bascule sur l'initiale). Un `refreshFromAniList`
  périodique existe déjà pour renouveler les URL.

### 3. Page profil sans aucun `h1` — Faible à moyen (a11y)

- **Fichier** : `src/components/tsuzuku/profile-view.tsx`
  (12 vues sur 13 ont leur `h1`, relevé automatisé à l'appui).
- **Cause** : le nom affiché n'existe que dans un champ éditable, aucun
  titre de page.
- **Piste** : `PageHeader` (« Mon profil » / eyebrow « Compte »), comme les
  autres vues.

### 4. Titres d'onglet périmés hors accueil — Faible

- **Fichier** : `src/components/tsuzuku/app-shell.tsx:145` ne met à jour
  `document.title` que sur `/`. `/friends`, `/lists`, `/messages`,
  `/profile`, `/watch`, `/admin` conservent le titre de la vue précédente
  (ex. « Ma liste — Tsuzuku » affiché sur Messages).
- **Piste** : `useEffect` titre par route (modèle existant :
  `u.$username.tsx:175`, `share.$token.tsx:41`).

### 5. Badge « non lus » sous le seuil de contraste — Faible (a11y)

- **Fichier** : `src/components/tsuzuku/app-primary-nav.tsx:113`
  (`bg-crimson text-white`, ~3,3:1 sur fond Nuit, texte 9 px).
- **Piste** : `text-bg` au lieu de `text-white` (~5,3:1 en Nuit, ≥ 5:1
  vérifié en clair — le token suit le thème, contrairement au blanc fixe).

### 6. Chronologie : « 0 encore en diffusion » — Faible (copie)

- **Fichier** : `src/components/tsuzuku/timeline-view.tsx:220`.
- **Repro** : visible sur la capture `audit-timeline-1440.png` — la mention
  s'affiche même quand le compteur est à zéro.
- **Piste** : ne l'afficher que si `stillAiring > 0`.

### 7. `window.confirm` natif × 7 — Faible (dette UX)

- **Fichiers** : `friends-view.tsx:437,456`, `u.$username.tsx:492,535`,
  `party.$roomId.tsx:563`, `admin-view.tsx:42`, `lists-view.tsx:408`.
- **Constat** : dialogue système bloquant, incohérent avec les confirmations
  maison déjà en place (suppression groupée `list-view.tsx:302`,
  retrait fiche `entry-modal.tsx:594`).
- **Piste** : généraliser le motif de confirmation maison.

### 8. Panneau « Conversations » vide étiré — Faible (visuel)

- **Fichier** : `src/components/tsuzuku/messages-view.tsx:415`.
- **Repro** : capture `audit-messages-1440.png` — sans conversation, le
  panneau occupe toute la hauteur fixe (`h-[calc(100dvh-12rem)]`) pour une
  seule ligne de texte.
- **Piste** : hauteur minimale + état vide compact quand la liste est vide.

## Remarques (non bloquant, à garder en tête)

- **R1.** Les `503` sur `/api/activity` et `/api/shared-lists` en dev viennent
  uniquement de l'auth désactivée — pas un bug prod. La vraie leçon est le
  constat n° 1 (dégradation UI).
- **R2.** Les champs du profil (`profile-view.tsx:194,202,426,435,444`)
  utilisent le même composant `Field` non associé qu'avait la fiche :
  appliquer le même correctif `htmlFor` (`entry-modal.tsx` déjà traité).
- **R3.** Flèches de navigation semaine de l'agenda en 32 px
  (`calendar-view.tsx:214,232`) : conformes WCAG (≥ 24 px) mais sous les
  44 px tactiles recommandés.
- **R4.** Couleurs festives codées en dur de la roulette
  (`roulette-view.tsx:718`) et repli `#a3e635` de `habits-card.tsx:78` :
  choix assumés, hors système de thèmes — à documenter plutôt qu'à corriger.
- **R5.** Les `console.warn/error` trouvés dans le code sont des logs
  d'exploitation légitimes, pas des oublis de debug. Aucun `TODO/FIXME`.
